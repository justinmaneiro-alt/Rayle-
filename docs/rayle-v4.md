# Rayle v4 — Volume, historique long, actualité défilante, corrections

Document de travail (2026-11-20, session autonome). Une section par phase : décisions, limites, ce qui n'a pas pu être fait.

## 0. Audit (avant toute modification)

### Architecture
- **Pile** : JavaScript natif (modules ES), pas de bundler pour le code ; `build.mjs` copie vers `dist/`. Hébergement statique relié au dépôt ; `git push origin main` publie. Tests : `npm test` (Node pur) + tests Chrome (`trader-pro/tests/*-chrome.mjs`).
- **Terminal** : page `agent-trading/front/or.html` + moteur historique `agent-trading/front/or/` (Lightweight Charts) ; la couche pro se branche via `trader-pro/terminal/integration.js` (`monterPro(T)`). Flèches MA200 : `ma200-h4.js` + registre ; flèches de niveaux : `niveaux.js` ; aides (régime, voyant, annonces, taille) : `aides.js` / `aides-ui.js` ; stats : `stats-fleches.js`.
- **Marchés** : `agent-trading/front/marches/*` (fenêtre, couverture-ui, données) + `trader-pro/marches/*` ; panneaux construits par `marches/donnees/api.js`.
- **Couverture** : `trader-pro/couverture/` (calcul, protection, fenêtre). **Portefeuille** : `trader-pro/portefeuille/` (IndexedDB + synchro D1 via Worker). **Investissement** : `trader-pro/invest/` (calcul nocturne → branche `donnees-invest`). **Accueil** : carrousel (`index.html`, `core/`, `galaxie/`), carte « À la une » alimentée par `actus-*.json`.

### Sources de données
- **Branche orpheline `donnees`** (GitHub Actions, `.github/workflows/donnees.yml`, cron 15 min) : `outils-donnees/snapshots.mjs` écrit actus, calendrier, Yahoo, bougies compactes, COT, panneaux Marchés, `pro-<id>.json` (j ≈ 1300, h4 ≈ 3600, h1 ≈ 700, m15 ≈ 500). Lecture navigateur par `agent-trading/front/donnees/couche.js` (ordre : PC → direct → snapshot → cache IndexedDB).
- **Temps réel** : Kraken (WebSocket/REST) dans le Terminal. Worker Cloudflare Portefeuille : D1, alertes Telegram, synchro.
- **Branche `donnees-invest`** : calcul nocturne de l'Investissement.

### Points faibles repérés à l'audit
- La couche de données essaie le **serveur du PC en premier** quand la page est servie par le PC ; sinon snapshot, sinon cache. Les cases « lu par le PC · copie locale » viennent de là.
- Les snapshots ne couvrent pas l'historique long (Daily ≈ 5 ans, H4 ≈ 2,3 ans, H1 ≈ 700 bougies).
- Aucun volume centralisé exploité hors volume Yahoo/Kraken de l'instantané.

## Décisions générales
- Nouveau code en modules **purs et testés** (Node) puis une interface mince ; style visuel sobre inchangé ; tout gratuit, sans clé.
- Rien ne dépend du PC : les données viennent de la branche `donnees` (robot GitHub), de la branche `historique` (nouvelle) ou d'API publiques appelées directement par l'appareil (Binance, Kraken).
- Un seul calendrier, un seul classement des annonces, une seule lecture de l'historique long : chaque règle est écrite à un seul endroit.
- Pièges rencontrés (à retenir) : le déclencheur `schedule` de GitHub Actions ne passe en pratique que toutes les 4 à 12 h ; les noms d'étapes YAML contenant « : » doivent être entre guillemets ; l'outil Bash mange les antislashs (patchs écrits avec Write/Edit) ; un script de patch resté dans le dossier temporaire d'une ancienne session a été exécuté par erreur (voir « Incident » plus bas).

## Phase 1 — Corrections des bugs vus en vidéo (faite)
1. **Accueil / dock** : `core/commun/accueil-rayle.js` limite chaque colonne (Météo, Ce jour-là, À la une) à l'espace entre son haut et le haut de la barre du bas (mesuré en direct, recalculé au redimensionnement, à la rotation et à chaque changement de contenu) ; si « Ce jour-là » ne tient pas, il est masqué avant que la météo ne défile. Testé sur 5 tailles (PC, tablette paysage et portrait, téléphone, petit PC) : `trader-pro/tests/accueil-chrome.mjs`.
2. **Phrase sous les boutons** : la phrase « en tendance, les flèches MA200… » n'est plus affichée en ligne ; elle est dans l'info-bulle de la pastille de régime.
3. **Régime** (`trader-pro/terminal/aides.js`) : avant, seule l'efficacité de Kaufman sur 20 bougies comptait (3 jours en H4) : l'or 18,8 % sous sa MA200 Daily pouvait s'afficher « Range ». Maintenant **tendance = efficacité ≥ 0,30 OU prix à plus de 3 ATR de sa MA200 avec une MA200 qui penche du même côté**. La pastille dit « Tendance baissière » et l'info-bulle (Détails) donne la méthode et les valeurs (efficacité, écart en % et en ATR).
4. **Marchés figés PC éteint** : cause trouvée : le robot `donnees.yml` est déclenché par `schedule */15`, mais GitHub ne l'exécute en réalité que toutes les 4 à 12 h (mesuré : trous de 11 h). Le workflow est maintenant une **boucle de 5 h qui republie toutes les 5 minutes** (lot rapide), les bougies toutes les 15 minutes, l'horaire toutes les heures, puis **se relance lui-même** (`gh workflow run`, autorisé avec le jeton du workflow) ; le déclencheur `schedule` reste en filet de sécurité. Les libellés « lu par le PC » des fichiers produits par le robot deviennent « robot GitHub, différé ».
5. **Calendrier unique** : `trader-pro/marches/calendrier.js` contient désormais `classerEvenement` (Discours / Décision de taux / Compte rendu / Statistique) et `evenementsMajeurs` ; la carte et la fenêtre Marchés, la miniature d'accueil, la Couverture d'événement et les bandes du Terminal l'utilisent (même source `calendrier2.json`, même fenêtre, mêmes étiquettes). Cause du bug : la Couverture reconnaissait « ECB President Lagarde Speaks » comme une « BCE (décision de taux) » et le Terminal « FOMC Member … Speaks » comme une décision de la Fed. **Limite** : les dates BCE / Fed codées en dur pour l'historique (2021-2025) n'ont pas été vérifiées contre les calendriers officiels depuis cette session (pas d'accès hors flux publics) ; elles ne servent qu'au comportement passé.
6. **Couverture** : « Fiable » exige maintenant en plus |corrélation sur 250 jours| ≥ 0,5 (sinon « Partielle », avec la raison) ; « Gain abandonné » est affiché en % de la position et en € (si la taille est saisie).
7. **Investissement, financières** : cause : pour AXA le secteur et l'industrie manquaient (`estFinanciere` retournait faux), la société était donc traitée comme une industrielle ; repli sur le nom (AXA, BNP, Société Générale, Allianz…). À l'affichage, quand la société est financière : ni EV/EBITDA, ni flux libre, ni DCF (ni DCF inversé), ni Altman, ni ROIC, ni dette nette/EBITDA ; le nom de la méthode devient « Multiples (PER historique) ». **Graham reste replié** (« Information »). Les données déjà calculées sont masquées à l'affichage ; le recalcul nocturne appliquera la règle à la source.
8. **Fraîcheur** : l'en-tête dit « calcul il y a X » et rappelle que le prix est la dernière clôture de chaque bourse ; la fiche dit « prix il y a X (dernière clôture) · calcul il y a Y ». Deux âges, deux étiquettes.
9. **Portefeuille** : la synchro existait déjà mais exigeait de saisir l'adresse et le code du Worker sur chaque appareil. Nouveau : **lien d'appairage** (Réglages → « Copier le lien pour les autres appareils »), `config.js` l'applique au chargement (`#pf=…`). Import sur un appareil → visible partout dès que le Worker Portefeuille est déployé. **Limite** : le Worker Portefeuille n'a jamais pu être déployé depuis ce poste (pas de `wrangler login`) ; tant qu'il ne l'est pas, rien ne se synchronise.
10. **Autres bugs trouvés et corrigés** : voir la liste en fin de document.

## Phase 3 — Terminal classique : fond noir et historique long (faite)
1. **Fond noir uni** (`terminal-pro.css`). Le coloriage vert / rouge selon la tendance MA200 est une **option, désactivée par défaut** (réglages MA200, clé `fondTend` : l'ancienne clé est ignorée pour que l'ancien choix n'impose pas le coloriage).
2. **Bougies normales partout** : l'historique de référence n'est plus gris ; la bande « Historique de référence Binance XAUUSDT » est remplacée par une **fine ligne pointillée « raccord de source »** avec une pastille « i » dont l'info-bulle donne la source, les dates et l'écart mesuré.
3. **Historique long** : `outils-donnees/historique-long.mjs` + `.github/workflows/historique.yml` (hebdomadaire, à la demande, et à chaque changement du script) → branche orpheline `historique` : `<actif>/<unité>/<année>.json.gz` + `index.json`. Mesuré au premier passage (CI) : or Daily 2003 → (7 338 bougies, Dukascopy XAUUSD bid), H4 depuis 2018, H1 depuis 2023 ; Nasdaq 100 Daily depuis 1985 (Yahoo ^NDX), H4/H1 Dukascopy ; S&P 500 Daily depuis 1970 (Yahoo ^GSPC) ; EUR/USD Daily depuis 2003 (Dukascopy) ; Bitcoin Daily depuis 2014 (Yahoo avant le 17/08/2017, Binance ensuite), H4 8 ans, H1 3 ans ; Solana Daily depuis 2020. Binance par le miroir public `data-api.binance.vision` (l'API principale refuse les serveurs américains de GitHub). Dukascopy par le paquet `dukascopy-node` installé **seulement dans le workflow** (rien ajouté à package.json ; il n'a pas pu être installé sur ce poste, le script a été validé en CI).
   - **Chargement à la demande** : `trader-pro/terminal/histo-long.js` charge 6 années de Daily (3 en H4, 2 en H1) au premier affichage puis **une année de plus à chaque arrivée au bord gauche** (branché dans `agent-trading/front/or/historique-or.js`, qui garde son comportement d'avant sans historique long). Le temps réel (Kraken, ou Yahoo pour les autres) se raccorde à la fin.
   - **Écart mesuré et recalage** : rapport médian (cours direct / historique long) sur les 250 dernières bougies communes (600 en H1), écrit dans `index.json` ; tout l'historique long est multiplié par ce rapport (les bougies récentes ne bougent pas, le raccord est continu). Mesuré : or ×1,0004 (Daily : ×0,9996), Nasdaq ×1,00003, S&P ×1,000004, EUR/USD ×1,0003, Bitcoin ×0,9986, Solana ×0,9987. **L'écart est écrit dans le panneau MA200 (« Historique long »)**, à côté de la source et des dates. H4 : la grille H4 du Terminal et celle de l'historique long sont décalées de 2 h pour l'or ; l'écart H4 est celui du H1 (même niveau de prix), dit explicitement.
   - **MA200 et flèches recalculées sur l'historique complet** (Daily jusqu'à 40 ans, H4 8 ans) ; les flèches plus anciennes que 36 h ne sont jamais annoncées. Test Chrome : or Daily **19,9 ans** (6 212 bougies) après quelques défilements.
4. **Niveaux historiques majeurs** (`niveaux-historiques.js`, activés par défaut en Daily, option) : plus haut historique, plus hauts / bas annuels (6 ans), zones de réaction répétée (≥ 3 pivots sur 10 ans) ; lignes fines pointillées, étiquettes courtes (« Plus bas 2024 · 1 984 »), au plus 8, à moins de 25 % du prix, fusionnés à moins de 0,5 ATR.
5. **Fluidité** : Lightweight Charts ne dessine que la partie visible ; mesuré : le coût par image ne dépend pas du nombre de bougies (1 800 → 6 200 bougies : même durée) ; le rendu logiciel du test est lent par nature (≈ 220 ms par image) : **à confirmer sur la tablette réelle**.

## Phase 4 — Mode « Volume » (fait)
**Sélecteur Classique | Volume** en haut à droite du Terminal (`integration.js`) ; le mode Classique est inchangé (le terminal classique reste monté dessous). Le mode Volume (`trader-pro/volume/`) est chargé à la première ouverture, s'ouvre en **H4** puis garde le dernier choix (actif, unité, calques), unités H1 / H4 / Daily, fond noir uni.

### Données de volume : la vérité par actif (badge sous le titre, avec l'âge)
| Actif | Volume | Côté (delta) | Carnet / transactions |
|---|---|---|---|
| Or | **Binance XAUUSDT** (perpétuel, volume réel) ; option « futures COMEX GC » (volume institutionnel, Yahoo, prix des futures) | réel (côté de l'agresseur) avec Binance ; estimé avec COMEX | Binance (WebSocket) ou Kraken PF_XAUUSD au choix |
| Bitcoin, Solana | Binance (réel) | réel | Binance ou Kraken |
| Nasdaq 100, S&P 500 | futures CME NQ / ES via Yahoo (instantanés du robot, différé), H4 construit depuis le H1 | **estimé** depuis la bougie (position de la clôture × volume) | **aucun carnet gratuit** : le panneau le dit et affiche le volume par niveau de prix |
| EUR/USD | futures CME 6E via Yahoo | estimé | aucun |
Le robot publie désormais `bougies-NQ_F|ES_F|6E_F-1h|1d.json` (lot « bougies »). **Limites** : l'or au comptant et le forex n'ont pas de volume centralisé (sur XTB c'est un volume de ticks) ; Yahoo est différé ; l'historique de transactions gratuit est court → **l'empreinte (footprint) n'existe que pour les bougies vues en direct** (H1, or / Bitcoin / Solana, à fort zoom) ; sinon elle est masquée et la bougie montre son volume et son delta.

### Contenu
- **Graphique** : bougies normales ; **profil de volume de la zone visible** à droite (histogramme horizontal, part acheteuse / vendeuse, zone de valeur à 70 % en plus clair), **POC**, **VAH / VAL**, **HVN** (triangles) et **LVN** (pointillés) ; **VWAP semaine et mois** (±1 σ) et **VWAP ancrés** à la main (bouton « Ancrer VWAP » puis toucher une bougie ; bandes ±1 et ±2 σ ; gardés par actif et unité) ; **POC nus** des semaines et mois précédents (lignes pointillées) ; **MA200 et ses flèches** ; **mes dessins** (lignes, boîtes, trendlines, Fibonacci) relus depuis le stockage des dessins ; **volume et delta écrits sur chaque bougie** quand le zoom le permet.
- **Panneau 1** : volume coloré selon le delta (barres > 2× la moyenne mises en évidence), moyenne sur 20 bougies, **CVD** (marqué « estimé » si le delta l'est). **Panneau 2** : **MFI 14** avec zones 80 / 20 (ou **RVOL** au choix) ; divergences prix / MFI calculées (`divergencesMfi`) mais non tracées : décision de ne pas surcharger.
- **Panneau de droite** : carnet en échelle (12 niveaux de chaque côté), **déséquilibre** acheteurs / vendeurs sur 10 et 25 niveaux, **murs** (≥ 4 × la médiane, surlignés et tracés en lignes fines), **carte de chaleur** (option, instantané toutes les 10 s sur 3 h), **gros flux** (seuil = max(5 × médiane, 98ᵉ centile) des tailles récentes), **supports / résistances par le volume** (3 à 5, profils sur 20 / 60 / 120 bougies + POC nus, force = volume relatif + réactions passées + ancienneté + accord des sources, séparés d'au moins 1 ATR).
- **Flèches Volume** (à la clôture seulement ; la bougie en cours n'est jamais évaluée ; testé : un préfixe de la série donne les mêmes flèches) : **absorption** (volume > 1,5×, petit corps, mèche du côté du niveau, delta qui se retourne), **cassure validée** (clôture au-delà de VAH / VAL / HVN venant de l'autre côté, volume > 1,5×, delta dans le sens), **faux breakout** (sortie nette de la zone de valeur sans volume, retour net dedans). Une flèche par événement (même type et même sens : au plus une toutes les 8 bougies, 12 pour le faux breakout). Libellé : « Absorption H4 · VAL 3 580 · volume ×1,9 · delta ↑ » ; voix de Rayle, notification et Telegram (même canal que les autres flèches, première mise en route : tout est marqué comme vu, rien n'est annoncé) ; **coupables par type**.
- **Statistiques** : les trois types sont dans le panneau Stats (taux de réussite, R médian, cas, « non significatif » sous 30 cas) ; `stats-fleches.json` régénéré **avec l'historique long** (or H4 12 763 bougies, Daily 6 086, etc.). **Limites** : delta **estimé** dans l'historique (pas de côté disponible), volume de ticks (Dukascopy) pour l'or / les indices / EUR/USD ; ces statistiques sont proches du hasard (repère 33 % à 2 R / stop 1 R) : ne pas les lire comme un avantage.
- **Voix** : « Rayle, analyse le volume de l'or en H4 » (POC, position par rapport à la zone de valeur, déséquilibre du carnet, murs proches, niveau le plus fort, dernière flèche) ; « passe en mode volume » ; « reviens au mode classique » ; « ancre un VWAP ici » ; « montre-moi les POC nus ». Les commandes retrouvent le terminal même dans un cadre de l'application, ou l'ouvrent.
- Tests : `volume-test.mjs` (31 : profil, VA, HVN/LVN, VWAP, POC nus, MFI, RVOL, carnet, flèches, absence de futur), `volume-live-test.mjs` (23 : flux, carnet Kraken, empreinte, reconnexion, données), `volume-chrome.mjs` (PC, tablette, téléphone sur l'or et le Bitcoin en H4 : carnet vivant, 3 panneaux, profil, S/R, VWAP).

- Deux lecteurs de calendrier dupliqués (`marches-donnees.js` et `trader-pro/marches/calendrier.js`) → un seul.
- Couverture d'événement et bandes du Terminal : discours pris pour des décisions de taux (voir point 5).

- **Incident** : un script de patch resté dans le dossier temporaire d'une ancienne session (`p32.mjs`, ciblant `Documents/Projets/Rayle-/trader-pro/commun/dashboard.js`, une ancienne copie du projet) a été exécuté par erreur deux fois. Le contenu du fichier est identique à son HEAD (`git diff --ignore-space-at-eol` vide) ; seuls les fins de ligne ont changé (CRLF → LF). ### Limites connues
- **Worker Portefeuille / dessins / journal** : jamais déployés depuis ce poste (`wrangler login` indisponible) → pas de synchro entre appareils tant que ce n'est pas fait (`trader-pro/worker/LISEZMOI.md`).
- **Volume** : voir le tableau des sources ; delta estimé hors Binance ; pas de carnet gratuit pour les indices et l'EUR/USD ; empreinte limitée aux bougies vues en direct ; Binance / Kraken en WebSocket public (indisponibles dans certaines régions ou derrière certains réseaux : l'état du flux est affiché).
- **Historique long** : H4 de l'or construit depuis le H1 Dukascopy (volume de ticks) ; EUR/USD et indices : volume de ticks, pas de volume réel centralisé ; données Dukascopy « bid ».
- Les dates BCE / Fed codées pour l'historique de couverture ne sont pas revérifiées (voir point 5).
- Les statistiques de flèches (MA200, niveaux, Volume) restent proches du hasard : ce sont des repères, pas un avantage démontré.
